# 风险雷达改版方案（状态页 v1 → v2）

> 状态：**已定案、未排期**。本文档是完整规格，实现挂事件触发条件（见第 6 节）。
> 决策日期：2026-11-27。依据快照：2026-11-26T18:30:49Z（data 分支最新）。

## 0. 一句话

把状态页从「给 deployer 的健康体检表」改成「给交易员/质押者的喂价风险雷达」：**分级依据从"偏离度"换成"偏离度 × 名义敞口"，弃养市场从告警列表里拆出来独立成灰色区**。代码（src/ 六模块）零改动，只动页面生成器。

---

## 1. 以前是什么样（v1 现状盘点）

线上页 `index.html`（data 分支，由采样 workflow 每 30 分钟重建）：

**信息架构**
- 按DEX 分节（xyz / flx / vntl / …），每节一张表，**按 dev 降序**平铺全部资产。
- 每行：asset、oracle、mark、dev（%）、OI（原始数量）、24h vol、状态徽章。
- 顶部汇总卡：DEXs 数、live assets 数、**critical dev = 0、warn dev = 1**、24h 量。
- 徽章分级：ok / warn / crit / dead，阈值按**单一偏离度**划线（≈ warn 0.5%、crit 1%）。
- 弃养 DEX（量归零）与其他 DEX 同构展示，仅徽章换灰色。

**用 11-26 真实快照实测，v1 的三个盲点：**

1. **头部结论失真。**汇总卡写着 "critical 0 / warn 1"，页面叙事是"生态基本健康"。但同一份快照里：xyz:ANT 偏离 0.23%（23bps）、名义 OI ≈ **$210M**；xyz:MU 偏离 0.25%、OI ≈ **$162M**——两者都被标 **OK**。约 $370M 敞口躺在 ≥20bps 偏离的市场里，页面 headline 却是零告警。
2. **OI 列没有参与任何判断。**OI 只是表格里一列原始数字（1,545,215.4 这种），既没换算成名义值，也不进分级。一个 0.58% 偏离、$786K 量的市场和 0.25% 偏离、$211M OI 的市场，在 v1 眼里前者更危险（SNXX 排第一、拿 warn），后者 OK——**排序和真实资金风险是反的**。
3. **弃养与活险混在一页。**hyna:LIT 偏离 48.4% 与 xyz:HOOD 偏离 26.8bps 用同一套徽章语义。前者是墓志铭（量 $0，无人受伤，永远不会再发生清算），后者才是风险。混排既稀释了活险的信号，也浪费了"7/10 已弃养"这个最有传播力的统计。

**v1 回答的问题**：「每个市场喂价健康吗？」——这是 deployer 视角（我的运维正常吗），而 deployer 侧买家近乎不存在（10 个 DEX 死 7 个、头部自建）。

## 2. 现在是什么样（v2 目标形态）

改动后页面（规格示意已用 11-26 真实数据验证）：

**信息架构（三层）**

1. **顶部指标带**：全网 24h 量（$2.84B）· 活险市场数（红）· 观察名单数（黄）· 已弃养 DEX 数（7/10）。
2. **活市场风险表（页面主体）**：只列活 DEX 中偏离或敞口触线的市场，**按名义敞口 × 偏离排序**。列：市场、oracle↔mark（bps）、预估名义 OI、24h 量、判读（一句话人话，如"高 OI × 高偏离，清算是真事故"）。行底色：红 / 黄 / 白。
3. **弃养灰色区（独立折叠块）**：7 个量归零 DEX 平铺，每格 DEX 名 + 区内最大偏离，配一句定语："不是风险，是墓志铭"。

**分级规则（由 src/deviation.mjs 现有分级逻辑派生，不新造阈值体系）**

| 级别 | 判据 | v1 对应行为 |
|---|---|---|
| 红 | 偏离 ≥20bps **且** 名义 OI >$100M | v1 里标 OK |
| 黄 | 偏离 ≥15bps，**或**名义 OI >$250M 且偏离 ≥10bps | v1 里多数标 OK |
| 灰 | 24h 量 ≈ 0 | v1 与活市场同列 |

阈值写在页面方法论段落里公开，允许被引用者检验。

**方法论落款（页面固定尾段）**：偏离定义（|oracle−mark|/oracle，Hyperliquid 公开 API）、OI 名义估算方式（数量×mark，索引类按 asset 类型校准）、刷新频率、守卫库链接。这是页面可被第三方引用的前提。

## 3. 逐条对照：改什么、为什么

| # | 维度 | v1 | v2 | 为什么 |
|---|---|---|---|---|
| 1 | 受众/视角 | deployer（运维体检） | 交易员/质押者（资金风险） | deployer 侧需求已验证为空；交易员与 HYPE 持有者是今天真实存在的人群 |
| 2 | 排序主键 | 偏离度降序 | 名义敞口 × 偏离 | 真实清算风险 = 错的价格 × 在场的钱；只看偏离会让 $786K 量的死叉排 $211M OI 的活险前面 |
| 3 | OI 语义 | 原始数量，不参与判断 | 名义美元值，进分级 | 让"多大"可比较、可引用 |
| 4 | 汇总卡 | critical 0 / warn 1 | 活险 2 / 观察 8 / 弃养 7/10 | v1 头部结论与数据矛盾；v2 头部即风险结论 |
| 5 | 弃养处理 | 同列、灰徽章 | 独立灰色区 + 定语 | 死市场是论据不是告警；独立成区才有传播力 |
| 6 | 判读列 | 无（只有徽章） | 一句话人话 | 徽章是术语，判读是可截图引用的语言 |
| 7 | 方法论 | 无 | 固定尾段 | 没有方法的数字不可被引用 |
| 8 | 代码改动 | — | 仅页面生成器 + 分级接线 | 守卫库冻结在 v0.1.0 的纪律不变 |

## 4. 实现清单（约半天）

1. `scripts/`（采样管线内，页面生成处）：
   - OI 名义换算：`notionalUsd = qty × markPx`，索引/股票/商品按 asset 命名分类校准单位。
   - 分级函数：接 `src/deviation.mjs` 现有 assess 输出，叠加 OI 条件得 红/黄/白；量 ≈0 判灰。
   - `index.html` 模板按第 2 节三层结构重写；方法论段落为常量。
2. **不动**：src/ 六模块、测试、workflow 调度链路、data 分支结构。RSS/alarms.jsonl 输出顺带加（<20 行），其余一律不做。
3. 验证：用最近 7 个快照回放生成器，人工核对红/黄名单与 11-26 示意一致。

- **不排期。**触发条件（任一即做）：① 某 HIP-3 市场出现 20bps+ 偏离且 OI >$100M；② 新 deployer 起量（24h 量 >$10M）；③ 喂价类事故进入公共讨论。
- 判死线不变：改版上线起 90 天零外链引用 → 停分发、仓库转存档；2027-02-24 到期评审照旧。
