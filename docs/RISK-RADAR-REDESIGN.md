## 0. 一句话

把状态页从「给 deployer 的健康体检表」改成「给交易员/质押者的喂价风险观察雷达」：**分级依据从"偏离度"换成"OI 加权偏离观察"，低活跃市场从告警列表里拆出来按 OI 分流——量≈0 且 OI>0 进陷阱区（红），连续 96 快照量≈0 且 OI≈0 进墓志铭区（灰）**。代码（src/ 六模块）零改动，只动页面生成器。

**指标定性（重要）**："OI 加权偏离"是**观察性指标**，不是清算风险估算或潜在损失。它回答"哪里有大敞口正对着喂价异常"，不回答"会亏多少"。页面所有文案用观察性语言（"盯紧""异常组合"），禁止"清算是真事故""无人受伤"等结论性表述——那需要清算引擎数据支撑，本页没有。

## 1. 以前是什么样（v1 现状盘点）

线上页 `index.html`（data 分支，由采样 workflow 每 30 分钟重建）：

**信息架构**
- 按DEX 分节（xyz / flx / vntl / …），每节一张表，**按 dev 降序**平铺全部资产。
- 每行：asset、oracle、mark、dev（%）、OI（原始数量）、24h vol、状态徽章。
- 顶部汇总卡：DEXs 数、live assets 数、**critical dev = 0、warn dev = 1**、24h 量。
- 徽章分级：ok / warn / crit / dead，阈值按**单一偏离度**划线（≈ warn 0.5%、crit 1%）。
- 弃养 DEX（量归零）与其他 DEX 同构展示，仅徽章换灰色。

**用 11-26 真实快照实测，v1 的三个盲点：**

1. **头部结论失真。**汇总卡写着 "critical 0 / warn 1"，页面叙事是"生态基本健康"。但同一份快照里：xyz:ANT 偏离 0.23%（23bps）、名义 OI ≈ **$210M**；xyz:MU 偏离 0.25%、OI ≈ **$162M**——两者都被标 **OK**。约 $370M 敞口躺在 ≥20bps 偏离的市场里，页面 headline 却是零告警。
2. **OI 列没有参与任何判断。**OI 只是表格里一列原始数字（1,545,215.4 这种），既没换算成名义值，也不进分级。一个 0.58% 偏离、$786K 量的市场和 0.25% 偏离、$211M OI 的市场，在 v1 眼里前者更危险（SNXX 排第一、拿 warn），后者 OK——**排序和真实资金风险是反的**。
3. **弃养与活险混在一页。**hyna:LIT 偏离 48.4% 与 xyz:HOOD 偏离 26.8bps 用同一套徽章语义。前者（r2 实测：该 DEX 全部市场 OI=0）是考古对象，后者才是观察对象。但混排最大的问题在反方向：量≈0 而 OI>0 的市场（如 mkts:USTECH）在 v1 里同样被淹没——那才是最该单独拎出来的。混排既稀释了活险的信号，也浪费了"7/10 低活跃"这个最有传播力的统计。

**v1 回答的问题**：「每个市场喂价健康吗？」——这是 deployer 视角（我的运维正常吗），而 deployer 侧买家近乎不存在（10 个 DEX 死 7 个、头部自建）。

## 2. 现在是什么样（v2 目标形态）

改动后页面（规格示意已用 11-26 真实数据验证）：

**信息架构（四层）**

1. **顶部指标带**：全网 24h 量（$2.84B）· 红/黄/陷阱/墓志铭计数（红优先，黄排除红与墓志铭）。
2. **活市场风险表（页面主体）**：只列非墓志铭 DEX 中偏离或敞口触线且 OI>0 的市场，**按 OI 加权偏离排序**。列：市场、oracle↔mark（bps）、预估名义 OI、24h 量、观察判读（一句话，观察性语言）。行底色：红 / 黄 / 白。
3. **陷阱区（红色独立块，r2 新增）**：量≈0 但 **OI>0** 的市场——头寸被卡住、没有新鲜成交、喂价还在漂移。这不是弃养，是 SK Hynix 型事故的前夜形态。实测（11-26 快照，量阈值 $5,000）：`para:TOTAL2`（名义 $0.53M、24h 成交 $1.2K）与 `para:30Y`（名义 $0.1M、成交 $31.5）。注：r2 曾引 mkts:USTECH 为例，实为归因错误——该市场 OI=0，mkts 中 OI>0 的是 BVIV（在正常交易）。
4. **墓志铭区（灰色折叠块）**：连续 N 个快照（默认 96 个 ≈ 48h）量≈0 **且** OI≈0 的 DEX。单快照量≈0 **不足以**判死——采样失败、无交易时段都可能造成单点零值。每格 DEX 名 + 区内最大偏离 + 判定窗口，配一句定语："不是告警，是考古"。

**分级规则（观察阈值，与任何执行前 guard 阈值无关）**

| 级别 | 判据 | 说明 |
|---|---|---|
| 红 | 偏离 ≥20bps **且** 名义 OI >$100M | **优先级最高**：先判红 |
| 黄 | 偏离 ≥15bps **且 OI>0**，**或**名义 OI >$250M 且偏离 ≥10bps | 黄是敞口观察：OI=0 的偏离没人持仓，是噪音不是风险（r4 实现时发现 124 个假黄全部来自弃养 DEX 死市场）；黄 = 不满足红、且非墓志铭 DEX（红/黄条件有重叠，必须显式写优先级，否则顶部计数与正文对不上） |
| 陷阱 | 量≈0 **且** OI>0 | 独立红色块，与红/黄互斥 |
| 灰 | 连续 96 快照量≈0 且 OI≈0 | 需要跨快照状态，不能单点判定 |

**阈值溯源（诚实声明）**：20bps / $100M / 15bps 是**本页自设的观察阈值**，为排版和注意力分配服务，不是从清算引擎或 Insight 执行前 guard（100bps 提醒 / 1000bps 阻断）推导的，两者不得混用。阈值写在页面方法论段落里公开，允许被引用者检验；后续若积累偏离-清算配对数据，再回头校准。

**缺失数据处理（防两类误判）**：任一关键字段缺失或非法（oraclePx / markPx / openInterest / dayNtlVlm 为 null、负数或解析失败）时，该市场**不进任何分级**，单列"数据缺失"小节展示（市场名 + 缺哪个字段 + 快照时间）。理由：坏数据判成红 = 虚假告警；坏数据判成灰 = 把还活着的市场埋进墓志铭。两类都伤页面信用。

**白色市场展示规则**：未触线的活市场不逐行展示（v1 平铺 178 行是页面失去焦点的根源），聚合成每 DEX 一行汇总——"xyz：其余 116 个市场未触线，最大偏离 8.0bps（xyz:XYZ100）"。完整明细仍可在每 DEX 折叠块里展开，照顾想核对全量的读者。

**方法论落款（页面固定尾段）**：偏离定义（|oracle−mark|/oracle，Hyperliquid 公开 API）、OI 名义估算方式（数量×mark，索引类按 asset 类型校准）、刷新频率、守卫库链接。这是页面可被第三方引用的前提。

## 3. 逐条对照：改什么、为什么

| # | 维度 | v1 | v2 | 为什么 |
|---|---|---|---|---|
| 1 | 受众/视角 | deployer（运维体检） | 交易员/质押者（敞口观察） | deployer 侧需求已验证为空；交易员与 HYPE 持有者是今天真实存在的人群 |
| 2 | 排序主键 | 偏离度降序 | OI 加权偏离（观察性指标） | 注意力分配 = 在场的钱 × 偏离幅度；只看偏离会让 $786K 量的市场排 $211M OI 的市场前面 |
| 3 | OI 语义 | 原始数量，不参与判断 | 名义美元值，进分级 | 让"多大"可比较、可引用 |
| 4 | 汇总卡 | critical 0 / warn 1 | 红 2 / 黄 8 / 陷阱 1 / 低活跃 7/10（红优先计数，黄排除红） | v1 头部结论与数据矛盾；v2 头部即观察结论，且计数与正文严格对应 |
| 5 | 低活跃处理 | 同列、灰徽章 | 按大类分流：陷阱区（量≈0 但 OI>0）/ 墓志铭区（96 快窗口量≈0 且 OI≈0） | 量零不等于无人受伤——mkts:USTECH 实测反例；真死与被困必须分开 |
| 6 | 判读列 | 无（只有徽章） | 一句话观察语言 | 徽章是术语，判读是可截图引用的语言；禁用结论性表述 |
| 7 | 方法论 | 无 | 固定尾段 + 阈值溯源声明 | 没有方法的数字不可被引用 |
| 8 | 缺失数据 | 无规则（坏值直接渲染） | 不进分级，单列"数据缺失"小节 | 坏数据判红=虚假告警，判灰=活埋，两类都伤信用 |
| 9 | 白色市场 | 全量平铺 178 行 | 聚合为每 DEX 一行汇总，明细折叠 | 页面焦点给触线市场，全量可核对但不占屏 |
| 10 | 代码改动 | — | 仅页面生成器 + 分级接线 | 守卫库冻结在 v0.1.0 的纪律不变 |

## 4. 实现清单（1-2 天，r2 上修）

1. `scripts/`（采样管线内，页面生成处）：
   - OI 名义换算：`notionalUsd = qty × markPx`。**单位校准是主要工作量**：HIP-3 覆盖股票/指数/商品/加密，OI 的合约单位各不相同，须按实际 API 字段逐一核对，不能靠 asset 命名猜。
   - 分级函数：红/黄/陷阱/灰四级，**红优先于黄**；灰区需要跨快照状态（96 快照窗口），采样器要持久化或回读 data 分支历史。
   - 缺失数据守卫：关键字段 null/负数/解析失败 → 不进分级，落"数据缺失"小节。
   - 白色市场聚合：未触线市场按 DEX 聚成一行汇总 + 折叠明细。
   - `index.html` 模板按第 2 节四层结构重写；方法论段落为常量。
2. **不动**：src/ 六模块、测试、workflow 调度链路、data 分支结构。RSS/alarms.jsonl 输出顺带加（<20 行），其余一律不做。
3. 验证：用最近 7 天快照回放生成器，人工核对红/黄/陷阱/缺失名单；**单位校准与回放核对才是主要工时**，页面模板本身只占小头。

## 5. 明确不做（冻结清单）

- X 告警 bot —— 触发条件：页面拿到第一个真实外链引用。
- Insight pre-trade 接入 —— 触发条件：出现 OI 起量的新 HIP-3 市场或首个异常偏离事件。
- PriorSeal 快照锚定 —— 触发条件：下次真实事故。
- 库新功能（节假日日历、monitor 持久化等）—— 永久冻结，v0.1.0 即终态。

## 6. 排期与判死线

- **不排期。**触发条件（任一即做）：① 某 HIP-3 市场出现 20bps+ 偏离且 OI >$100M；② 新 deployer 起量（24h 量 >$10M）；③ 喂价类事故进入公共讨论。
- 判死线不变：改版上线起 90 天零外链引用 → 停分发、仓库转存档；2027-02-24 到期评审照旧。
- 成本封顶：1-2 天（r2 上修：单位校准 + 跨快照回放是主要工时）。
